控制说明

· 暂停：不再扫描、不再上传；已进行的分片会自然收尾。
· 继续：立即恢复检测（下个周期生效）。
· 停止：进程优雅退出。若由任务计划程序/systemd 托管并配置了自动重启，会被再次拉起。

立即行动

需要立刻扫描或上传时，请在服务器上执行：
bdsync scan --root … / bdsync send --db …
看板不发起扫描/上传任务（design §13：控制面只做状态机级操作）。

关于

bdsync —— 本地目录单向备份到百度网盘的常驻守护进程 bdsync

它做什么

把一个本地目录的变化，持续、增量、低噪声地复制到网盘的对应目录。 方向只出不进：本地新增/修改会上传，本地删除与改名会同步到远端； 而网盘侧被别的客户端改动的文件，本软件只归档、不删除 —— 备份目录不该由备份工具单方面清空。

主要功能

· 增量：稳态下只处理真实变更，不重扫、不重算哈希、不重传
· 镜像：远端清单永远 ≡ 本地清单（含删除与改名传播）
· 远端历史：任何会被镜像销毁的旧版本先归档进 .history/，默认留 90 天
· 秒传优先：网盘已有相同文件时零带宽完成
· 断点续传：分片进度持久化，中断后只补缺失的块
· 崩溃安全：队列落 SQLite，检测结果即刻持久化，断电不丢已检测到的变更
· 低噪声：空闲态 CPU ≈ 0%，内存 < 30 MB，磁盘不休眠唤醒
· 看板：状态/队列/日志实时查看，可暂停、继续、停止

明确不做

· 网络盘 / 网络共享：网络挂载上无法可靠检测变更，启动时校验，不符合直接拒绝运行
· 双向同步 / 冲突合并：复杂度高得多，备份场景不需要
· 裸删除：删除与覆盖一律先归档，不做「不归档就删远端」
· 图形界面：用 CLI + 本地看板，零 GUI 依赖
· 对外暴露的服务：看板只监听回环地址，且默认关闭

核心逻辑 · 数据怎么流动

  Detector                SQLite (WAL)              Sender
  ─────────                ───────────              ──────
  Windows NTFS ─┐
                ├─ 只碰本地元数据 ──▶ entry 表          ┌─▶ 预建目录
  其他本地 FS  ─┘   与索引 diff       + pending 状态     │   秒传探测
                    (size, mtime)      kv 表（游标）     │   分片上传
                        │                  ▲            │   AIMD 限流
                        │ 写入（零网络）    │ 批量领取     │   回写索引
                        └──────────▶ 崩溃安全边界 ◀──────┘
                                                   ▼
                                            百度网盘 API
Detector 与 Sender 之间只有 SQLite，没有任何内存队列或 channel。 这条边界同时买下三样东西：检测耗时与网络状况彻底解耦（检测永远不会卡在网速上）、 断电后已检测到的变更不丢、两边可以各自独立演进。

四条设计原则

P1 · 检测与发送彻底解耦
检测只碰本地元数据，绝不因网络阻塞
P2 · 无变更时绝对空闲
没活干时不消耗任何 CPU 与磁盘 IO
P3 · 状态可持久化
批处理不产生数据丢失风险
P4 · 只支持本地固定磁盘
网络盘上无法可靠检测变更，启动即校验

几个关键机制

· 稳定性闸门：大量软件会写文件（下载中的视频、数据库、Office 临时文件）。 正在被写的文件传上去就是坏数据 —— 发送前重新 stat，(size, mtime) 变了就退回队列，不计为错误。
· 水位 + 间隔 双触发：到点才排空，但积压超过高水位立即触发不等间隔； 排空一旦开始就持续到低水位（work-conserving），而不是「5 分钟内传完」—— 否则几万文件的首次同步会变成每 5 分钟猛冲一次然后被限流打断。
· AIMD 自适应并发：连续成功缓慢加并发，遇限流立即减半并退避； 退避带 full jitter，否则十几个 worker 同时重试就是惊群，能把账号打死。
· 错误分类：登录过期立即停机告警；31079 秒传失败降级为普通上传 —— 那不是错误；网络错误才退避重试。
· 宁可多传，不漏传：所有不确定情况一律偏向重传。多传浪费一次带宽，跳过是数据丢失。

检测后端

Windows 本地 NTFS 走 USN Journal（无损、可验证，空闲时零文件打开、 零磁盘唤醒）；其他本地文件系统走 WalkDir 全量扫描， 天然完整，是所有平台的基线与降级路径。

常驻方式

就地便携：exe + bdsync.yaml + index.db + 凭据 + logs/ 在同一文件夹，整体搬走即可。可用任务计划程序 / nssm / systemd 托管， 停止走 SIGINT/SIGTERM。
